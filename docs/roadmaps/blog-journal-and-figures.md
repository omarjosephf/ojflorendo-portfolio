## Why this needs two phases, not a prompt change

On 30 September 2026 the owner approved a redesign of the blog, the
"proof-first journal", and asked for the writing agents to use interactive
graphs and animations. Three things in the current code stand in the way:

1. **The post format allows four kinds of content**: headings, paragraphs,
   lists and callouts (`src/lib/blog/schema.ts`). The post checker rejects
   anything else, so an agent asked for a chart either cannot comply or
   produces a post that fails.
2. **The Writer's instructions forbid first person and code**
   (`blog-writer-live-v3` in `src/lib/blog/live/prompts.ts`), while the
   approved design is written in the owner's own voice.
3. **The sources are written in the third person.** Every factual sentence
   must quote an allowlisted source word for word
   (`src/lib/blog/live/sources.ts`), and those sources say "OJ is…" and
   "He…". A Writer told to say "I" would mix the two voices, the flaw that ruled
   out the first Phase 18.4 draft (`run-20260930-014625`).

## The approved design

The owner keeps the approved mockup privately; it is not in this repository.
Its elements:

- an "In short" summary at the top of every post;
- a "How this was made" disclosure that folds open;
- three post types: case study, build notes and explainer;
- body text of 17px on phones and 18px on laptops, about 65 characters a line;
- sidenotes in a margin column on wide screens, opened by tapping on phones;
- hand-drawn diagrams, including a step-through diagram the reader advances
  with a button;
- charts drawn from numbers, with the same numbers available as a table;
- takeaways, and a contact box tied to the post's topic; and
- on the index, an introduction with the owner's photo, one featured case
  study, and cards that give each post's result in one sentence.

The mockup's other ideas are listed under [out of scope](#out-of-scope).

## Owner decisions, 30 September 2026

1. **Placement.** Both phases come straight after phase 15a, so the live site
   does not change while the answer captures run. They come before phase 18.5
   and the nine-example calibration set, so the Reviewer is calibrated on the
   final post format. The owner accepted that this moves phase 16 back by the
   length of both phases.
2. **Voice.** The owner writes a small set of first-person notes in the
   owner's own words. Once approved and allowlisted, they are the only route
   to first person: a sentence containing "I", "me", "my", "we" or "our" is
   allowed only when it contains an exact quote from those notes, and code
   enforces this. Every other sentence stays neutral. The exact-quote rule is
   not relaxed.
3. **Hand-drawn look.** rough.js, a small MIT-licensed drawing library, run
   only on the server so readers download none of its code, subject to the R2
   dependency review in phase 18.6. If it fails that review, the figures use
   plain SVG shapes.
4. **Scope.** The two phases below.

## 18.6 acceptance criteria

1. The post checker accepts post format version 2. Each new block is data
   only (labels, numbers and short text) with strict limits, and unknown
   fields are rejected as they are today. Version 1 posts still validate and
   render, and the live post's approved text is unchanged.
2. The bar chart is drawn on the server as SVG, and its bars start at zero.
   Its screen-reader description and its table view are generated by code from
   the same numbers, never written by a model. Bars grow once when scrolled
   into view; with reduced motion they appear finished.
3. The step-through diagram is the only new code that runs in the reader's
   browser. A button advances one step at a time and each step is announced to
   screen readers. It works by keyboard, nothing moves on its own, and without
   JavaScript the steps show as a numbered list.
4. The index and article pages follow the approved design, within the
   out-of-scope list. The hand-drawn font is self-hosted through `next/font`,
   so there is no runtime Google Fonts request and no Content Security Policy
   change. New page copy, such as the index introduction and the contact box,
   is written or approved by the owner before it ships.
5. Motion follows ADR-0010: finite and event-driven, never looping.
6. A test post that uses every new block passes axe on `/blog` and the
   article, keyboard-only use, reduced motion, 200% zoom, phone and laptop
   widths with no horizontal scroll, and a Lighthouse mobile Performance score
   of 90 or more on the article.
7. ADR-0027 is accepted, the
   [blog pipeline threat model](../threat-models/blog-live-pipeline.md) covers
   the new blocks, and the full gate passes once on the unchanged candidate.
8. After owner approval, the live post renders in the new layout in
   production.

## 18.7 acceptance criteria

1. The Writer's output format accepts the version 2 blocks, and the Writer's
   instructions (v4) offer them as a menu. The Writer never writes code, HTML
   or Markdown.
2. Each chart value names the claim it comes from, and code rejects the draft
   unless that number appears in the claim's exact text, as digits or as
   number words ("fifteen" as well as "15").
3. Step-through labels are two to four words and contain no numbers. Each
   step's caption is an exact quote of a cited claim.
4. The owner's first-person notes are written, approved and allowlisted, and
   code rejects a first-person sentence that does not contain an exact quote
   from them. Until the notes exist, the Writer keeps the neutral voice.
5. The Reviewer (v3) assesses every chart value and every step as it assesses
   citations today. The SEO Agent reviews figure titles, and the Critique Agent
   sees the figure-check results.
6. Live runs stay within a spend cap the owner approves immediately before
   them. Proposed: US$3 in total and US$1 per run.
7. One agent-written post with at least one verified figure is approved by the
   owner and published. Auto-publish stays off.
8. ADR-0027's Verification block records the runs, costs and checks, and the
   full gate passes.

## Rules both phases keep

- Figures are data, never code. No model output is executed or inserted as
  HTML.
- No new library runs in the reader's browser. rough.js, if approved, runs
  only on the server.
- Every number on the page reaches it through a checked route.
- The exact-quote rule, the independent Reviewer and the owner's approval of
  every post stay in force.
- A published post is never rewritten without the owner's approval.

## Out of scope

- The smaller Ask E.V button that hides while the reader scrolls. It is part
  of E.V's interface, which the E.V release evidence covers.
- Short screen-recording videos: none exist yet.
- Post-type filters on the index, until there are about ten posts.
- A before-and-after slider, until the chart and step-through diagram have
  proved themselves.
- Hand-built interactive pieces for individual flagship posts.
- Phase 18.5 (scheduling, auto-publish and the calibration set), the OpenAI
  and Anthropic fallbacks, and the Model Scout.

## Risks

- **Misleading charts.** Bars start at zero, descriptions are generated from
  the data, and the Reviewer checks every value against its claim.
- **An uncalibrated Reviewer.** It scored both passing Phase 18.4 drafts 100,
  including the flawed one the owner did not choose. Every post therefore still
  waits for the owner's approval.
- **Accessibility or speed regressions** from the new pieces. The 18.6
  criteria test for both.
- **Scope creep** from the mockup's other ideas. The out-of-scope list holds
  the line.

## Rollback

Post format version 2 only adds to version 1, and the Writer v3 instructions
stay in the code. Reverting the pull request, or redeploying the previous
production deployment, restores the current blog.
